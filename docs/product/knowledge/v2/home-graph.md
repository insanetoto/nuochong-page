# 知识首页：Obsidian 式知识全景图谱

2026-11-02 · 设计稿 v1 · **planned**。目标是把“知识首页”从卡片列表升级为可探索的关系图谱，让员工看到知识的结构、依据和影响，而不是装饰性动画。本文只做设计，不包含前端实现或图数据库选型。

## 1. 目标与非目标

**目标**

- 一屏看清“有哪些知识、它们如何关联、依据来自哪里、哪些正在失效”。
- 支持从全局到局部的探索：全公司/空间 → 条目 → 邻居 → 来源片段。
- 所有节点、边、计数都经过服务端权限过滤；图谱不能成为侧信道。
- 与 Obsidian 的图谱体验一致：力导向布局、悬停高亮、拖拽/缩放、局部图谱、筛选与分组。
- 大图可退化：节点过多时聚合/截断，并提供列表与搜索作为无障碍与低性能兜底。

**非目标**

- 不做 3D 图谱、宇宙动画或营销式粒子效果。
- 不把图谱当唯一导航；搜索、目录、阅读页仍保留。
- 不做外部系统节点、实时协同编辑；**跨空间证据引用**不在首期，跨空间条目关系允许（双方可见才返回）。
- 不在客户端做权限过滤或全量下载。

## 2. 页面结构

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 知识库 / 知识首页        [空间 ▾]   [搜索条目、概念、来源…]   [任务] [头像]   │
├───────────────┬──────────────────────────────────────────────┬───────────────┤
│ 知识导航       │ 知识全景                                      │ 选中节点       │
│ 知识首页 ●     │ 统计：128 条目 · 36 概念 · 9 待审 · 3 风险     │ 年假制度       │
│ 搜索           │ [全部▾] [节点类型▾] [关系▾] [现行▾] [布局▾]   │ 类型：条目      │
│ 问答           │                                              │ 空间：人力资源  │
│ 来源管理       │            ○──────○                          │ 状态：现行 v4   │
│  知识空间      │           / ╲    / ╲                         │ 依据：3 片段    │
│  知识导入      │      ○───○   ○──○   ○                        │ 关系：6         │
│  知识发布      │         ╲  │  /     │                        │ [打开条目]      │
│ 我的任务       │          ○─○─○──────○                        │ [聚焦此节点]    │
│ 组织与权限     │                                              │ [复制链接]      │
│               │ [＋][－][适应屏幕][全屏]   图例 ●条目 ●概念 ○来源│ 相关：报销/假期 │
└───────────────┴──────────────────────────────────────────────┴───────────────┘
```

- 桌面：左侧导航 216px，中间画布自适应，右侧抽屉 320–360px（可收起）。
- 画布最小高度 `calc(100vh - 顶栏 - 统计栏)`；不出现页面级横向滚动。
- 移动端：默认“列表 + 关系摘要”，图谱作为可选视图，限制节点数，手势缩放；不依赖 hover。

## 3. 节点与边

### 3.1 节点类型

| 节点 | 本体类 | 默认显示 | 颜色/形状 | 大小 | 标签 |
| --- | --- | --- | --- | --- | --- |
| 条目 | `nc.kb:KnowledgeEntry` | 是 | 品牌蓝实心圆 | 按连接度/片段数 | 标题（过长截断） |
| 概念 | `nc.kb:Concept` | 是 | 青色描边圆 | 按被引用次数 | 概念名 |
| 来源 | `nc.kb:SourceRevision` | 否（可开） | 灰蓝方点 | 固定小 | 制度编号/版本 |
| 空间 | `nc.kb:KnowledgeSpace` | 聚合层 | 半透明区域/标签 | — | 空间名 |

首期不显示“答案”“任务”“用户”节点，避免把运行数据混入知识图谱。能力/课程节点在后续版本按需加入，并单独权限过滤。

### 3.2 边类型

| 边 | 语义 | 默认 | 方向 | 证据 |
| --- | --- | --- | --- | --- |
| `cites` | 条目引用来源片段 | 开（来源层开启时） | 条目 → 片段/来源 | 逐字引用 |
| `about` | 条目属于概念 | 开 | 条目 → 概念 | 概念分配 |
| `relatedTo` | 条目相关 | 开 | 无向（存双向） | reason + weight |
| `supersedes` | 同条目不同修订替代 | 历史/维护层（虚线） | 新修订 → 旧修订 | 发布派生的修订级记录 |
| `conflictsWith` | 依据冲突 | 开（琥珀/红） | 无向 | 冲突证据 |
| `partOf` | 片段属于来源修订 | 来源层开启时 | 片段 → 修订 | locator |
| `derivedFrom` | 编译产物来自来源 | 维护者视图 | 修订 → 来源 | 生成记录 |

修订节点仅在经授权的历史/维护层展示，ID 使用 `revision:<revisionId>`；员工默认现行条目视图不将 supersedes 折叠为条目自环。supersedes 不通过条目关系写命令创建。

边默认不显示文字；悬停或选中时显示关系名与原因。没有 reason 的 `relatedTo` 不允许写入（见本体约束）。`relatedTo` / `conflictsWith` 允许跨空间，但仅当调用者对两端空间均有读权限；`cites` 仍限同空间证据。

## 4. 视图模式

| 模式 | 行为 | 适用 |
| --- | --- | --- |
| 全局图谱 | 当前空间/多选空间/全部可见范围的条目+概念 | 发现结构与孤岛，含跨空间关系 |
| 局部图谱 | 以选中节点为中心，1–2 跳邻域 | 阅读时理解上下文 |
| 空间分组 | 按空间聚类，显示空间标签 | 多业务域 |
| 概念分组 | 按概念层级聚类 | 主题浏览 |
| 来源层 | 叠加来源节点与 `cites` 边 | 维护者核验依据 |
| 待审/风险层 | 只显示待审、失效、冲突节点 | 运营处理 |

“全局/局部”是同一查询参数的不同 `depth`（0=全局，1/2=局部），不是两套数据。空间筛选支持多选；跨空间边不会扩大任何一端的可见范围。

## 5. 交互

- **加载**：骨架屏 + “正在构建知识图谱”；不显示虚假节点数。
- **悬停**：高亮节点与直接邻居，其他节点降低透明度；显示 tooltip（标题、类型、状态、连接数）。
- **点击**：选中并打开右侧抽屉；双击/“打开条目”进入阅读页；来源节点打开原文核验并定位片段。
- **拖拽**：节点可拖动并临时固定；松开后不自动弹回（`pinned` 仅本地会话）。
- **缩放/平移**：滚轮/触控板缩放，拖动画布平移；`＋/－/适应屏幕/全屏`；缩放范围 0.2–3。
- **展开**：节点菜单“展开邻居”（增加 depth）、“只看此空间”、“隐藏此类型”。
- **筛选**：空间（多选）、节点类型、关系类型、状态（现行/待审/失效/冲突）、时间 `asOf`；筛选同步 URL。
- **搜索**：顶部搜索定位节点并高亮；无结果给建议，不暴露无权标题。
- **分享**：复制带 `focus`、`types`、`space`、`depth` 的链接；接收者权限不同则自动裁剪。
- **键盘**：`Tab` 进入画布，方向键在邻居间移动，`Enter` 打开，`Esc` 取消选中；提供“列表视图”等价操作。
- **减少动效**：`prefers-reduced-motion` 下关闭力导向动画，直接布局。

## 6. 数据契约（planned）

命令：`knowledge.graph.query.v1`（只读，`knowledge:read`，按空间范围校验）。

输入：

```json
{
  "spaceIds": ["space-hr"],
  "nodeTypes": ["entry", "concept"],
  "relationTypes": ["relatedTo", "about", "supersedes"],
  "status": ["published"],
  "focusId": "entry-annual-leave",
  "depth": 1,
  "asOf": "2026-11-02T00:00:00+08:00",
  "limit": 300
}
```

输出：

```json
{
  "nodes": [
    {"id": "entry-annual-leave", "type": "entry", "label": "年假制度", "spaceId": "space-hr",
     "status": "published", "revision": 4, "degree": 6, "size": 18,
     "summary": "员工年假申请、天数与审批", "updatedAt": "2026-10-30T10:00:00+08:00"}
  ],
  "edges": [
    {"id": "rel-1", "type": "relatedTo", "source": "entry-annual-leave", "target": "entry-expense",
     "weight": 0.8, "reason": "同属人力资源制度", "evidenceIds": ["frag-9"]}
  ],
  "stats": {"entries": 128, "concepts": 36, "pending": 9, "risks": 3},
  "truncated": false,
  "graphVersion": "pub-2026-11-01T00:00:00Z",
  "asOf": "2026-11-02T00:00:00+08:00"
}
```

规则：

- 服务端仅从发布快照绑定的关系/概念/分配修订生成现行图谱，再按当前权限和有效性裁剪；禁止读取最新草稿覆盖已发布内容。不可见节点不返回、不计数。
- graphHash 覆盖快照封存的关系、概念及分配；修改候选不影响现行图谱。跨空间目标换版后旧边隐藏，不自动改绑；历史快照只能在当前授权/有效性允许范围内重建展示。
- 节点/边 ID 稳定；`graphVersion` 由发布快照 + 授权 epoch + 本体版本组成，客户端缓存必须带它。
- `truncated=true` 时返回聚合簇（按空间/概念）与 `next` 提示，不静默丢数据。
- 读取实时校验来源有效期与 ACL；撤回/撤权返回裁剪后的图，不返回旧缓存。
- 图查询不返回正文全文；摘要限长，详情走条目/片段命令并重新验权。

## 7. 权限与隐私

- `knowledge:read` 只代表“可读某空间”，具体节点还要通过空间可见范围与来源 ACL 交集。
- 已发布图谱只使用 `knowledge:read`；待审/草稿/风险层需 `knowledge:edit`/`review`/`publish`，不能靠 UI 开关。
- 边只在两端节点都可见时返回；不能通过边推断隐藏节点存在。
- 跨空间关系：仅当 actor 对两端空间都有 `knowledge:read` 且节点本身可见时返回；一端不可见则整条边不返回，不能借此推断另一端存在。
- 统计按可见集合去重；跨空间重复节点只计一次，不暴露另一空间的数量；管理员也不自动读取他人私有内容。
- 来源节点默认关闭，避免通过文件名/编号泄漏；维护者视图单独授权。
- 图谱查询与导出记录审计（actor、范围、节点数、graphVersion），不记录正文。
- 缓存键：actor + 授权 epoch + 发布快照 + 本体版本 + 筛选条件；撤权后旧缓存不可命中。

## 8. 性能与规模

| 指标 | 目标（待实测） |
| --- | --- |
| 首屏可交互 | 300 节点 < 1.5s（内网） |
| 图查询 P95 | < 300ms（300 节点，含权限过滤） |
| 交互帧率 | 60fps（≤1,000 节点）；2,000 节点降级 |
| 最大返回 | 2,000 节点/5,000 边，超出聚合 |
| 展开延迟 | < 500ms（1 跳，100 节点） |

实现建议（设计阶段，不锁定依赖）：服务端 SQL 递归/邻接查询 + 发布快照过滤；客户端 Canvas/WebGL 力导向；布局在 Web Worker；节点标签按缩放级别显示；聚合簇可展开。首期不做服务端预计算全图布局，避免缓存与权限耦合。

## 9. 空态、错误与降级

| 场景 | 表现 |
| --- | --- |
| 无空间 | 引导“前往来源管理 → 知识空间创建”，不显示示例业务节点 |
| 有空间无发布 | 显示“尚无已发布知识”，给导入/发布入口（有权限时） |
| 图查询失败 | 保留筛选与搜索，显示重试；不显示“0 条知识”冒充成功 |
| 被截断 | 顶部提示“已聚合显示 300 个节点”，提供列表/缩小范围 |
| 权限变化 | 自动重载并提示“可见范围已更新”，不闪现旧节点 |
| 低性能设备 | 自动切换列表视图，保留搜索与阅读 |

## 10. 无障碍与移动端

- 画布外提供“列表视图”，表格列：标题、类型、空间、状态、连接数、更新时间；支持排序与分页。
- 画布节点有可读标签；键盘焦点可见；颜色不是唯一编码（形状/标签/纹理辅助）。
- 对比度符合 WCAG AA；边颜色对色盲可辨；不依赖 hover 才能获取关键信息。
- 移动端默认列表；图谱视图限制 150 节点，双指缩放，点击节点打开底部抽屉。

## 11. 验收标准（设计验收，后续实现复用）

1. 员工只能看到有权节点/边；用两个账号验证同一 URL 返回不同裁剪结果，且无标题/计数泄漏。
2. 选中条目可看到来源片段、版本、状态与关系原因；点击来源可定位原文（文本行/页码/时间码）。
3. 撤回来源或收紧 ACL 后，刷新图谱不再出现相关节点/边；问答与搜索同时失效。
4. 跨空间关系：仅双方空间可见时出现；撤掉任一空间权限后边消失，另一端内容不泄漏。
5. 300/2,000 节点性能达标或按设计降级；截断有提示，不静默丢数据。
6. 键盘可完成“搜索→选中→打开条目→返回”；移动端 390px 无横向溢出。
7. 空库、无发布、查询失败、权限变化四种状态均有明确文案，不伪造数据。
8. `knowledge.graph.query.v1` 的 CLI 与 Web 返回一致；未实现能力不注册 ready。

## 12. 埋点与运营（可选，隐私优先）

仅记录聚合指标：图查询次数、平均节点数、截断率、聚焦来源比例、从图进入阅读/问答的转化；不记录搜索词全文、不关联个人绩效。管理员可关闭。
