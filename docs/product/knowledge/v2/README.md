## 1. 本轮目标

1. **知识首页 = 知识全景**：以类似 Obsidian 的关系图谱展示条目、主题与来源之间的可核验关系，支持缩放、聚焦、筛选和逐层展开；不是装饰性动画，也不是全量数据先返回再前端过滤。
2. **来源管理拆为三个子模块**：知识空间（建空间/分业务域）、知识导入（多格式文件→后台解析→可追溯片段→条目的待审区）、知识发布（人工审核后的知识发布，输出可被搜索/问答/图谱/API/CLI/MCP/培训使用的知识能力）。
3. **空间创建从首页移出**：首页不再承担管理动作；空库时引导到「来源管理 → 知识空间」。
4. **本体驱动**：空间是业务知识域，条目/片段/来源/关系/发布都有稳定类型与证据链；与三产品共享组织、授权、审批和任务语义。
5. **保持与公司产品一致**：官网蓝白主题、共享组织与权限入口、插件组合、版本化 commandId/schema/CLI、服务端授权、发布审批、撤回即时失效。

## 2. 非目标

- 不开发通用网盘、任意 URL 抓取、自动制度裁决、自动发布或自动改成绩。
- 首期不做跨空间证据引用；跨空间条目关系允许（双方可见才返回）；不做租户自定义本体、OWL 推理、图数据库、向量集群。
- 不以「图谱好看」替代检索质量、引用可核验和权限隔离。
- ASR/OCR 由外部大模型适配器提供；测试阶段只验证文本类来源（Markdown/TXT/PDF 文本层/DOCX）的识别与结构化，使用 DeepSeek 文本模型；音视频/扫描件不纳入测试；供应商、区域、保留期与密钥由平台统一配置。
- 不把模型生成的条目/关系/摘要直接发布；人工审核是硬门禁。

## 3. 与 v0 的关系

| 维度 | v0 已实现 | v2 设计变化 |
| --- | --- | --- |
| 首页 | 制度卡片列表 + 新建空间表单 | 知识全景图谱；新建空间移入来源管理 |
| 空间 | 首页创建，部门可见 | 独立空间管理页：编码、业务域、角色、配额、归档；创建走审批/审计 |
| 来源 | Markdown/TXT，≤20,000 字符 | 批次导入；PDF/DOCX/音视频（分阶段）；文件与批次独立状态 |
| 解析 | 编译直接生成页面草稿 | 解析生成**片段**，进入条目的待审区；片段可逐条审校 |
| 条目 | `knowledge_pages` + 修订 | 语义称“条目”，保留表名；增加条目类型、概念、关系、片段证据 |
| 审校 | 页面级 approve/reject | 片段审校 + 条目组装 + 提交审校；发布前统一检查 |
| 发布 | 单页发布/撤回 | 发布批次、排期、能力输出、回滚；发布快照 manifest |
| 能力 | 搜索、问答、API/CLI/MCP 雏形 | 能力目录与发布绑定；按能力显示消费者、配额和契约 |
| 图谱 | 无 | 读模型投影 + 查询 API + 前端全景 |

**兼容**：不重命名现有表；新增表/可空列；旧条目按**段落**回填片段，旧行号引用映射到段落片段；迁移与回填单列任务，不阻塞现有测试环境使用。

## 4. 信息架构

```text
知识库
├─ 知识首页（知识全景图谱）
├─ 搜索
├─ 知识问答
├─ 来源管理
│   ├─ 知识空间        # 列表 / 创建 / 设置 / 归档
│   ├─ 知识导入        # 导入批次 / 文件校验 / 解析任务 / 失败重试
│   └─ 知识发布        # 待审片段 / 条目组装 / 发布中心 / 能力输出 / 质量检查
├─ 我的任务            # 导入、编译、问答任务
└─ 组织与权限          # 共享插件入口，不在此重建人员/角色
```

| 页面 | 路由（planned） | 主要内容 |
| --- | --- | --- |
| 知识全景 | `/knowledge` | 图谱、统计、筛选、节点详情、搜索入口 |
| 搜索 | `/knowledge/search?q=` | 关键词/筛选/片段结果；无权限不泄漏 |
| 问答 | `/knowledge/ask` | 有依据回答、引用、进度、取消 |
| 知识空间 | `/knowledge/manage/spaces` | 空间列表、创建向导、设置、归档 |
| 空间详情 | `/knowledge/manage/spaces/:id` | 业务域、可见范围、角色、配额、统计 |
| 知识导入 | `/knowledge/manage/import` | 批次列表、新建导入、任务进度 |
| 导入详情 | `/knowledge/manage/import/:batchId` | 文件状态、失败码、重试/取消、片段结果 |
| 知识发布 | `/knowledge/manage/publish` | 待审队列、发布中心、能力输出、质量检查 |
| 条目审校 | `/knowledge/manage/publish/:entryId` | 三栏：片段/正文/证据与影响；通过/退回/发布 |

旧 `/knowledge/manage/changes` 与 `/knowledge/manage/sources` 保留重定向/兼容视图，迁移后移除；不破坏书签。顶部保留空间切换；无空间时显示“前往来源管理 → 知识空间创建”。

## 5. 角色与权限（复用现有实现）

| 动作 | 需要的权限（当前运行时） | 说明 |
| --- | --- | --- |
| 浏览/图谱/搜索/问答 | `knowledge:read`、`knowledge:ask` | 只返回可见空间与当前发布快照 |
| 导入文件、编辑片段/草稿 | `knowledge:edit`（空间范围） | 导入批次与片段审校草稿 |
| 审校片段/条目 | `knowledge:review`（空间范围） | 审校结论绑定内容 hash |
| 发布/撤回/能力启停 | `knowledge:publish`（空间范围） | 发布需显式审批；默认不能自批（单人/演示空间可配置豁免） |
| 创建空间 | `knowledge:publish`（全局）+ 审批 | 首期沿用；后续再评估是否拆 `knowledge:space:create` |
| 组织/角色管理 | 共享 `organization:*` / `access:manage` | 不在知识库内复制 |

**不做权限扩张**：`docs/product/knowledge/commands.json` 中的 `knowledge:space:read` 等是规划草稿，未在运行时实现；v2 契约以当前五个权限为准，新增权限必须单独迁移、评审并保持 API/CLI/MCP 同权。系统管理员不自动获得内容发布权；知识发布人不能管理工具或成绩。

## 6. 核心用户旅程

### 6.1 从视频制度到可引用条目

1. 空间负责人进入「来源管理 → 知识导入」，选择空间，上传 `员工手册.mp4`，填写制度编号、版本、生效期、可见部门。
2. 预检通过后创建导入批次；后台任务依次执行转写、分段、去重、分类，生成带时间码的片段，进入条目「年假制度」的待审区。
3. 审校人打开「知识发布 → 待审」，逐条接受/修改/合并片段，组装条目正文并逐段插入引用；提交审校。
4. 发布人核对依据、权限交集和影响范围，审批后立即/定时发布；发布快照暴露 `search/answer/graph` 能力。
5. 员工在知识全景点击“年假制度”，打开条目或来源片段；问答引用可定位到视频时间码。
6. 来源撤回或权限收紧：条目、图谱边、搜索、问答和培训快照全部失效，维护者看到影响清单。

### 6.2 从首页发现知识

1. 员工进入 `/knowledge`，默认看到自己有权的条目与概念；来源层默认关闭，避免噪声。
2. 搜索或点击节点：高亮邻居、显示关系标签；右侧抽屉显示条目摘要、来源数、最后核验时间。
3. 切换“只看现行”“按空间分组”“局部图谱（1–2 跳）”；URL 记录筛选，可分享给同权限同事。
4. 无权限节点不出现、不计数、不提示存在；撤回/过期在图中消失或标记失效（仅维护者可见）。

## 8. 设计一致性检查

- **主题**：沿用 [页面设计 v1.1](../pages.md) 的官网蓝白 token、Logo、字体栈、卡片/按钮；图谱画布使用浅色底与品牌色节点，不引入第二套视觉语言。
- **共享能力**：空间角色、部门范围、审批、审计复用 `identity-company` / `organization` / `access-management`；知识库只声明资源与业务权限。
- **插件**：知识库 manifest 增加 `ontology` 片段与 `capabilities` 声明；禁用知识插件后不接新写、历史可读、图谱不返回该插件节点。
- **CLI/API**：新增能力全部有 commandId、输入/输出 schema、CLI 映射、授权/副作用/幂等说明；未实现标 planned，不注册 ready。
- **发布边界**：负责人已授权创建20项Issues，见[登记表](issue-registration.md)；本轮不启动实现/部署，按剩余准入和依赖逐项领取。
- **原型（2026-11-08更新）**：已输出[v2可点击原型](../../prototypes/knowledge-v2.html)及[页面/交互交接](prototype-design.md)，已于2026-11-08由负责人评审通过。原型为合成数据、无业务API，不代表v2运行UI或图谱能力已交付；原[knowledge.html](../../prototypes/knowledge.html)保留为v1历史参考。

## 9. 已确认决策（2026-11-08）

| 决策 | 结论 | 设计影响 |
| --- | --- | --- |
| ASR/OCR 供应 | 由外部大模型适配器提供；测试阶段只用 DeepSeek 对文本类来源做识别/结构化，不测试音视频/扫描件 | 外部供应商、区域、保留期、密钥由平台统一配置；未配置时明确 `PARSER_UNAVAILABLE`，不伪造转写 |
| 自批发布 | 单人/演示空间允许经独立治理审批开启；默认关闭 | 普通知识负责人不能自行开关；策略版本变化使旧内容审批失效，见来源管理§2.4 |
| 空间改名 | 允许修改显示名；编码创建后不可变，旧链接稳定 | 如需改编码，新建空间并迁移，不原地改 |
| 跨空间边 | 允许条目间跨空间关系；仅当双方空间均可见时返回 | 跨空间**证据引用**仍按同空间约束；关系不改变条目所属空间与发布 ACL |
| 能力消费者/配额 | 不设产品级白名单或数量上限；消费者仍需注册、受限凭据、审计、可撤销；配额可配置，默认不限 | 外部 API 仍必须认证授权，不能匿名调用 |
| v0 片段回填 | 按段落切分来源文本，行号映射到段落片段 | 旧行号引用保留兼容；回填幂等、可重跑 |

## 10. 仍待确认

1. 片段审校的最小单位：逐段、按章节批量、还是模型建议后整节确认。
2. 关系类型首期清单：`relatedTo`、`supersedes`、`conflictsWith` 是否足够；是否需要 `prerequisite`。
3. 发布审批层级：单审校人 + 发布人是否满足试点；是否需要双人复核。
4. 图谱默认节点上限与聚合策略；是否需要“仅我的空间/全部可见”开关。
5. 外部大模型的供应商、区域、保留期、成本与合规（方向已定，具体选型待定）。
6. 跨空间证据引用是否在后续开放（当前只允许关系边）。
7. 培训快照的课程复核规则与成绩影响范围。
