# 共享组织、人员、角色与权限插件

2026-11-01 · v1 · planned。用户明确：部门、人员和角色权限统一服务企业知识库、企业 AI 工具、培训和考试，可封装为插件组合使用。本轮形成设计，不等于已有完整组织管理、SSO 或权限管理界面。

## 一套人员与组织，多个产品授权

统一人员 ID、部门树与成员关系，在同一平台部署中只维护一次。各产品声明自己的权限点和资源类型，使用同一授权服务判断调用者能否操作。产品不得另建员工主库、复制角色绑定或直接查组织插件数据库；允许版本化的可重建显示缓存，不允许它成为授权依据。

身份认证、组织关系、角色和内容权限分别建模。部门负责人不自动成为知识发布人、工具管理员或考试阅卷人。产品 A 的管理员不是产品 B 的管理员；系统运维管理员也不默认读取私有问答和成绩。

## 可组合的插件边界

| 组件 | 职责 | 组合与依赖 |
| --- | --- | --- |
| 平台可信执行核心 | 验证身份、执行统一授权判定、审批/幂等、持久状态与审计；所有入口强制调用 | 每套部署必需，不能由业务插件关闭或绕过 |
| `identity-company` 公司身份插件 | principal 与公司 personId 绑定、公司登录/受限服务身份、会话撤销；复用 OA-04 能力 | 员工产品部署必需；SSO 是可选适配，不重新实现密码产品 |
| `organization` 组织人员插件 | 部门树、人员最小目录、多部门归属、状态和变更事件 | 三产品共用；使用部门范围授权时必需，单一受限服务演示可不启用 |
| `access-management` 角色授权管理插件 | 角色模板、权限目录、资源范围绑定、授权管理界面与审计 | 员工产品必需；数据管理可插件化，最终判定由可信核心实施 |
| `directory-connectors` 外部目录适配插件 | 将选定企业目录映射为统一人员/部门 ID，增量同步与撤销 | 可选；没有厂商适配时可以受限 API/CLI 维护，不伪称已接入 SSO |
| `knowledge` / `enterprise-tools` / `learning` | 资源类型、业务权限点、产品角色模板及业务限制 | 依赖身份与授权管理；选择部门策略时额外声明组织依赖 |

首期共享插件均为经审查的第一方可信模块。未来第三方插件不能自称身份或授权提供者、任意返回 allow、提供伪造部门关系或直接写角色表；采用隔离适配和受限 API。授权管理界面关闭不等于授权校验关闭。

### 推荐组合

| 部署包 | 组合 | 行为 |
| --- | --- | --- |
| 知识库独立版 | 身份 + 授权管理 + 知识库；需要部门时加组织插件 | 不强迫安装工具或培训，仍保留权限隔离 |
| 企业套件 | 身份 + 组织 + 授权管理 + 任意多个产品插件 | 一次维护人员和部门，分别授予产品角色 |
| 外部系统集成版 | 上述组合 + 目录适配 + 受限机器身份 | 目录同步与业务连接器分开授权 |
| 封闭模型演示 | 现有管理员原生演示，可不装组织插件 | 不能据此开放为员工产品或宣称具备部门权限 |

安装时校验 manifest 的 required/optional dependencies 与所用策略。缺少依赖不能静默放开权限：员工产品拒绝启用或相关命令返回 DEPENDENCY_UNAVAILABLE。组织插件被排空/禁用时，依赖部门关系的授权拒绝，不能把失效部门当“全员”；未依赖组织的受限服务路径按原策略运行。卸载前展示角色绑定/资源 ACL 的影响，保留 ID、审计和历史，不级联删除制度、成绩或产物。

## 统一模型与授权语义

| 数据 | 字段和规则 |
| --- | --- |
| Person | personId、displayName、status；仅最小目录，不纳入薪资、证件等 HR 档案 |
| PrincipalBinding | principalId、issuer+subject、personId、kind；不能仅用 email 匹配身份，客户端不能提交自己的角色 |
| Department | departmentId、parentId、name、status、revision；禁止循环，归档不物理删除历史引用 |
| Membership | personId、departmentId、primary、validFrom/Until、revision；支持多部门；调岗用同事务替换有效关系 |
| PermissionDefinition | productId、action、resourceType、risk、schemaVersion；插件只能登记自己命名空间 |
| RoleDefinition | roleId、productId、permissions、revision；模板不等于已授予的权限 |
| RoleBinding | subjectRef（人/部门，独立用户组后续规划）、roleId、resourceScope、validity、approvalRef、revision；跨产品绑定必须逐产品明确 |
| AuthorizationContext | 服务端解析 person/principal、组织/授权 epoch、产品与资源状态；不接受客户端身份覆盖 |

授权按当前有效身份、产品可用性、角色动作、资源范围、业务约束和 ACL 共同判定，显式拒绝优先、默认拒绝。部门范围默认不继承子树；只有显式指定 `includeDescendants` 的动态子树授权才覆盖后续子部门。敏感范围默认固定部门 ID 列表，移动部门或扩大子树前须预览影响并审批。部门授权动态匹配当前成员，但跨来源知识页仍取全部来源权限交集。

`org-admin` 管组织，`access-admin` 在被委托范围内管授权；内容发布、工具高风险执行与考试评分分别属于业务角色。授权者必须拥有可委托的权限集合和范围，角色编辑不能通过修改已绑定角色扩大到自己无权委托的动作；敏感授权和放宽可见性需要服务端审批。无法满足授权条件时拒绝，不因 --yes、dry-run 或模型调用放行。

平台级恢复管理员如需设置，必须单独配置、强审计和有限使用，不作为默认日常全权角色。诊断接口只能检查当前调用者，管理员“模拟某人权限”如需另立独立权限与审计，不借 check 接口任意枚举他人资源。

## 三产品共用但不串权

| 共享对象 | 企业知识库 | 企业 AI 工具 | 培训和考试 |
| --- | --- | --- | --- |
| 部门/人员 | 制度可见范围、归口负责人 | 可用工具范围、运行归属、审批人 | 学习分配、考试对象、讲师范围 |
| 角色模板 | reader/editor/reviewer/publisher | tool-user/tool-maintainer/tool-approver | learner/instructor/exam-admin/grader |
| 资源范围 | 空间/来源/知识页/私有答案 | 工具/版本/运行/产物 | 课程/班次/试卷/答卷/成绩 |
| 业务附加限制 | 当前有效来源、审批 hash、来源 ACL 交集 | 外部副作用审批、运行者归属 | 试题保密、作答时间窗、客观评分与人工评阅 |

示例：某人调入财务部后，只有明确关联财务部的权限绑定才变化；不自动获得财务制度发布权，也不自动读取其他人的问答、运行和成绩。员工停用后所有产品新请求拒绝；排队任务在执行前重验，运行任务停止产生新的外部副作用，已提交不可逆操作进入审计/补偿，不能声称可以撤销已完成事实。既有成绩和审批记录保留原 personId 及当时快照。

## 变更传播与一致性

人员停用、成员关系变化、角色/绑定修改与授权 epoch 更新在数据库事务提交。每个产品执行敏感请求时读取可信的当前授权版本；授权服务不可用时拒绝，不使用过期 allow。缓存绑定 personId、productId、resourceScope、组织/授权 epoch；同一会话跨产品请求也要重新校验。

Outbox 发布 `organization.membership.changed.v1`、`organization.person.disabled.v1`、`access.binding.changed.v1` 等最小事件，各产品幂等刷新派生索引和待办。事件只用于异步传播，不能成为撤权即时生效的唯一机制。问答/下载/产物返回前再验权；知识编译读集合变化则结果失效重审，历史考试不无声改分。

外部目录以 sourceId + externalId + version 映射，企业主体 ID 不随邮箱或部门名称变更而改变；同步不允许创建外部传入的管理员角色。同步删除转停用/待核对，不直接抹去历史；离线/乱序/重放均受版本与 Inbox 去重保护。

## 公共管理页面（planned）

统一入口 `/admin/organization`（部门树、成员、调岗/停用）、`/admin/access`（权限目录、角色、作用域绑定与变更预览）、`/admin/directory-integrations`（目录同步、版本、失败与审计）。使用官网蓝白主题，与产品壳一致。

三产品菜单显示“组织与权限”，跳到同一共享插件路由，保留当前产品筛选；不各建一套人员/角色页面。共享界面显示授权影响预览（受影响产品、空间/工具/课程）与当前操作权限，不能只隐藏按钮。归口负责人/讲师选择器复用受限目录查询，不展示无权个人信息。原型新增“统一管理”页只展示组合与角色范围设计，仍为合成示例，没有组织变更能力。

## API、CLI 与插件契约

所有新增命令为 planned，草案见 [能力清单](commands.json)。使用版本化 commandId、JSON Schema 与 CLI 映射；完整 DTO/OpenAPI 在 IAM-01 评审冻结，未实现不进入 ready 能力发现。Web/CLI/MCP 复用统一 API，MCP 不默认开放组织写与授权命令。授权是高风险写操作，审批/幂等/expectedRevision 统一生效。

manifest 示例（设计字段，非已实现加载器）：

```json
{"id":"knowledge","requires":["identity-company@1","access-management@1"],"optional":["organization@1"],"conditionalRequires":{"departmentScopes":["organization@1"]},"permissionNamespace":"knowledge","adminLinks":["organization","access"]}
```

## 验收出口

- 同一人/部门在三产品使用稳定 ID，一次变更后新请求立即按新授权处理；跨入口 API/CLI/MCP 负例一致。
- 知识发布人不能管理考试成绩；讲师不能继承工具管理员；部门主管不能自动读私人问答；org-admin 不能给自己授予 publisher。
- 部门循环/重复身份/过期关系/乱序同步/重复幂等/并发修改有确定错误；停用和角色收紧期间的查询/下载/运行无过期权限放行。
- 不安装产品插件不会出现该产品可执行权限点；禁用组织插件时部门策略失败关闭；卸载不删历史证据。
- 共享页面使用同一官网主题，角色页显示 productId 与资源范围；原型不冒充后台实现或生产 SSO。
