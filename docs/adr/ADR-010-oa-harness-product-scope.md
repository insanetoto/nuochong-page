# ADR-010：公司OA以Harness为基座，撤销旧业务路线

状态：Accepted，2026-10-29用户明确验收本次OA基座调整与新路线图并批准合入集成分支；会话原文：“验收通过，合入集成分支”。关联Issue #31 / PR #38。本决策不代表六项后续任务已完成或授权生产发布。

## 当前决策

保留官网，以DeepSeek Harness作为未来公司OA基座，暂用官方web Profile的原生页面作OA首页。删除当前旧业务入口、模拟认证、员工管理及样式/示例；不迁入test分支上的培训/通知/工单演示。

具体OA业务模块以后依据公司实际需求重新规划，不沿用旧B—E里程碑、功能承诺或85–141人日估算。旧计划归档，原未执行B Issue按not planned撤销，不伪称完成。已验收A阶段原型和技术证据保留。

## 两个产品入口

官网 `/` 保留营销内容及基线。OA运行于独立原生Web服务，`apps/oa`启动同版本官方dsh、隔离状态/工作目录，本机管理员预览使用其真实启动认证和cookie，不制作仿UI。

官网 `/oa` 只跳转到管理员配置的无token地址；未配置明确503。此入口不代替原生认证，也不将launch token下发到官网。初期只面向本机管理员；正式员工访问须先完成OA-04身份/资源作用域，不能把Host owner权限变成所有员工权限。

## 继承与替代

继承ADR-001/002/003/004/006/008中的官网隔离、窄适配、版本锁定、任务可靠性、测试和发布边界；其“现有业务页面必须迁移”和旧阶段任务已被本决策替代。ADR-005/007的业务企业表、检索/向量和完整企业运营需求不再是当前必做项；只保留运行元数据与最小调用方授权原则，正式方案按OA任务确认。

ADR-009的CLI优先继续适用，首先覆盖Harness运行/会话/模型/工具。未来OA业务只有在独立需求评审后才增加命令，不能生成尚不存在模块的成功响应。产品CLI不会直接开放dsh owner接口给一般AI调用者。

## 验收与后续

旧/app路由404，旧演示登录/员工UI无入口；官网原基线通过；真实原生OA页面启动并完成浏览器认证/渲染验证；CLI/包独立运行；新路线具有具体任务/依赖/验收，旧Issue撤销状态与新计划一致。

当前能力边界、路线与估算见[新路线图](../refactor/roadmap.md)。实际公司发布、员工权限和业务功能均不因本机预览通过而被认定完成。
