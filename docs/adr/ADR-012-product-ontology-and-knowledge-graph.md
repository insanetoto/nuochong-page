# ADR-012：产品本体层与知识图谱投影

状态：**Proposed**，2026-11-02。用户要求“把本体论的方法论用于公司产品所有设计”，并授权先形成设计、暂不开发。本 ADR 只提出架构方向，尚未评审为 Accepted，不改变 [ADR-011](ADR-011-product-plugins-llm-wiki.md) 的 Proposed 状态，也不授权实现或发布。

## 背景

三产品共用身份、组织、授权、任务、审批和 Harness。当前知识库 v0 已有空间、来源、修订、条目（page）、引用、审校、发布与问答；若继续按页面与自由标签扩展，会出现：

- 知识首页只能列卡片，无法表达来源、主题、条目之间的关系与影响；
- 视频/音频导入产生的片段没有独立身份，无法逐段审核、引用和失效；
- 培训、工具无法用同一语义引用知识快照；
- 图谱、搜索、API 各自拼装关系，权限与证据规则不一致。

## 决策

1. **平台提供本体注册表**（`packages/platform` 的核心模块，不是可禁用业务插件）：产品 manifest 声明命名空间、版本与类/关系片段；加载器校验命名空间、重复 ID、major 兼容与依赖。
2. **知识图谱是投影，不是新主库**：节点/边从权威 PostgreSQL 表（空间、来源、片段、条目、关系、发布）生成；按调用者权限与当前发布快照过滤；首期不引入图数据库。
3. **片段作为一级证据对象**：`SourceFragment` 有稳定 ID、来源修订、locator（页/段/行/时间码）、textHash 与抽取器版本；发布条目必须能回溯到片段与来源修订。
4. **关系具名且有证据**：条目关系（`relatedTo`、`supersedes`、`conflictsWith` 等）带类型、方向、原因与证据；模型只能建议，人工确认后生效。
5. **本体版本独立治理**：语义化版本；新增可选类/属性为 minor，语义变化/删除/收紧为 major；运行时只读，变更走迁移与审计；不物理删除。
6. **权限在实例上执行**：图谱查询先算可见集合再生成边；不依赖前端过滤；关系不自动传播权限，显式规则除外。
7. **三入口同构**：图查询、片段、发布、能力输出都提供版本化 commandId/schema/CLI 映射；未实现标 `planned`，不注册 ready。
8. **首期不做 OWL 推理**：以 schema + 约束 + 应用校验满足审计与证据需求；JSON-LD/SKOS 导出与推理能力后续单独评估。

## 影响

- 正面：统一语义与证据链；图谱、搜索、问答、培训快照共用一套关系；权限与撤回可传播；对外契约稳定。
- 成本：新增本体注册表、片段表、关系表、导入批次表与图查询服务；v0 数据需增量回填；产品团队需维护本体片段。
- 风险：过度建模导致交付变慢；图谱性能与权限过滤复杂；音视频解析依赖外部 ASR 能力。对应缓解见知识库 v2 设计与任务拆分。
- 兼容：保留 `knowledge_pages` / `knowledge_revisions` 表名与 v0 契约；新增可空列/新表；不做破坏性重命名。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| 每个产品各自建关系表 | 上手快，但跨产品语义与失效传播重复，长期不一致 |
| 直接引入图数据库 | 图查询自然，但权威状态、事务、备份与权限仍需 PostgreSQL，增加双写与一致性风险 |
| 用 OWL/RDF 全量建模并推理 | 表达力强，但审计困难、团队成本高，与人工审校冲突；首期不需要 |
| 只做 UI 图谱、不建本体 | 展示快，但无法校验、无法跨产品复用，后续重做概率高 |

## 验证与评审

- 原型/设计阶段验证：图查询 SQL 在 300/2,000 节点下的性能与权限过滤；片段回填的幂等与定位正确性；撤回来源后图谱/搜索/问答一致失效。
- 安全验证：无权节点、边、标题、计数不泄漏；跨空间关系拒绝；撤权后缓存不返回旧图。
- 评审：架构负责人、产品负责人、安全评审；通过后另开实现任务与迁移计划，不以本 ADR 直接开工。
