### 明确的操作流程（解释既有AC，不新增业务命令）

- 编辑态：草稿归principal/session/space所有；一次确认冻结完整文件hash/引用/metadata、owner和operation token。
- 提交态：同一确认操作只分配一次幂等键；普通poll不失效，真实空间/身份变化则旧操作不可再写新上下文。
- 未知态：保存原完整输入与key。提供“核对原提交结果”，用原输入和同key调用既有create，读取幂等返回的原结果；不要求新增查询命令。网络仍未知时保持未知，不能生成新key盲发。
- 用户要改变文件/metadata：先核对未知原提交；已成功则展示原批次，再由用户明确选择新的导入操作；已明确业务失败则可返回编辑并在重新确认时生成新操作。不得只清某个按钮的key而遗忘旧请求。
- 迟到结果：成功及错误回调修改草稿/key/detail之前均检查原owner+operation仍为当前；旧结果不得清除新草稿，不以是否仍是相同空间替代用户/会话/操作身份。
