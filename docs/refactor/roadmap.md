## 基座形态

```mermaid
flowchart LR
 Public[公开官网] --> Static[独立静态/Worker入口]
 OA[OA首页：原生Harness Web] --> Core[Harness与受控运行服务]
 CLI[nuochong CLI] --> API[OA控制API与调用方授权]
 AI[外部AI工具] --> CLI
 AI -. 后续 .-> MCP[MCP适配]
 MCP --> API
 API --> Core
 Core --> Sessions[会话/运行/模型/工具]
 API --> State[运行状态/权限/审计]
 Future[未来OA业务模块：未规划] -. 经评审后扩展 .-> API
```

原生Harness Web当前作为受认证保护的公网测试管理员入口，不把其owner配置/工具权限直接授予普通员工。正式公司入口须先落实身份和作用域。CLI/API/MCP复用同一能力契约；不复制业务规则、不用shell拼接模型输入。

3. OA-06通过后，先选择公司一个真实痛点，写业务范围/角色/数据/CLI命令和验收标准，再决定首个业务模块。不能因旧原型曾存在就自动迁回员工、培训、知识或工单。
4. 公司发布与生产推广必须有独立批准；原生owner页面不得直接作为全员权限模型。
