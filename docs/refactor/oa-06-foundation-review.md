# OA-06 基座评审与有限 Go 决定

2026-10-30，Issue #37。前置 OA-01—OA-05 已由负责人分别明确验收；本提案与 OA-06 整体验收、生产发布是不同决定。产品代码验证基线为集成提交 `2e9b86eb4d393ea57df1a8e16f687d3cdc7ed746`；验证脚本作为本PR新增，脚本SHA256和脱敏结果见[同版本验证报告](evidence/oa-06-local-e2e.json)。

## 同一产品版本的实证

- 官方 Harness Web：隔离管理员环境启动真实页面，启动token换cookie并从URL去除、渲染按钮且无页面异常，不进行模型调用。原检查脚本两次因同步计数发生在异步按钮渲染前失败；改为等待可见按钮后诊断与修正脚本均通过。未修改官网、上游UI及其产品逻辑。
- 同版本正式 CLI 提交合成运行，控制API与PostgreSQL持久化，Worker用官方SDK调用真实DeepSeek，CLI读取成功终态，MCP读取同一运行与会话历史；另一合成主体读取返回404。
- 外部真实DeepSeek `deepseek-flash` 通过MCP调用 `auth.me` 和 `models.list`；外部模型2次请求，Worker提交1轮，Worker的provider HTTP请求数未逐一计量；金额unknown。密钥未提交或传入CI。
- 官网批准的16项源码/素材哈希一致；官网Linux构建与E2E、容器/故障恢复和CI门禁证据见PR51。Linux没有批准的截图像素基线，不能冒称该检查通过。

原生Web是独立的管理员owner入口，公司API/CLI/MCP是另一个受限身份边界；本次将它们在同一产品版本分别验证，并未通过原生Web完成公司身份到控制API的统一链路。控制API与MCP没有额外公网部署；外部SSO、全员Web入口、完整运营审计、限流和生产灾备尚未建设。真实SDK模型调用未与故障强杀同时进行；OA-05容器恢复使用合成执行器。

## 负责人决定

**有条件 Go：仅将已验收能力作为后续知识库设计的技术起点**，不认定为全员OA上线或生产就绪。保留上述身份、部署、故障、视觉及费用边界；正式上线需另行确定部署、业务身份、数据、运维与验收。若负责人要求此阶段必须具有统一员工Web或已上线控制API，结论应为No-Go，先立项补齐，不以测试样例代替。

下一轮需求方向：[规章制度知识库草案](oa-06-knowledge-discovery.md)。需求/权限/审批人和版本规则需产品负责人确认，评审通过后再拆分实现任务；本PR不创建知识库业务功能。
